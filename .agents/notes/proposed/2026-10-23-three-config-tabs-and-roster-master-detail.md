# Agent Note: 配置中枢收敛为三页签，名册用主从编辑器

Status: proposed

## Problem

模板把路由、名册、健康、会话审计放在四个一级页签，把名册做成 280px 卡片墙，`instructions` 在卡片里截断，编辑入口是 `href="#"`。若照此实现，配置页会同时承担低频写配置和高频读运行，第四个页签与现有会话 chip 重复；12 个角色、4000 字符级 instructions 时卡片墙必然溢出，而校验错误只能埋在字段下方或被保存条截断。

## Decision

配置中枢最多三个一级页签：路由链 / 委派名册 / 渠道健康。按会话绑定留在会话输入框 chip；故障转移历史留在 Modal；委派名册用 224px 列表 + 编辑器，列表独立滚动，校验摘要置顶；handoff 未实现前不显示空的名册页签。

准入门槛（可机械判定）：

1. 一级页签数量 ≤ 3；DOM 中没有第四个“会话/审计”页签。
2. 名册页签在 12 个角色时列表独立滚动（最大高 420px），选中项始终进入可视区；页面不被角色列表撑长。
3. `instructions` 是 textarea，不是卡片文本；4000 字符上限在校验中可判定；校验失败时摘要横幅在编辑器顶部可见，不依赖滚动。
4. 会话绑定的写入口只有 chip；配置页的绑定说明是只读句子。
5. handoff 总闸关闭时，名册页签不存在，或只显示明确的激活卡与空态，不注册工具、不显示假名册。

## Alternatives considered

1. 保持四个页签（模板做法）
   - 最强的理由：所有功能都在一级导航里，发现成本最低；用户不用知道“会话绑定在 chip、运行在右栏”。
   - 为何被否：把配置/运行两个时间尺度混在一起；第四个页签与 chip 重复；名册和健康会争抢页面高度；用户为了看运行状态必须离开对话。页签数量不是问题，混尺度才是。
2. 把所有配置搬进右栏
   - 最强的理由：只维护一个载体，配置和运行在同一个上下文里，右栏还能拖动到 648px。
   - 为何被否：344px 窄栏放不下名册/策略/预算的完整编辑；配置是低频写操作，塞进常驻运行栏会让右栏变成设置抽屉，反而遮住运行信息。
3. 名册继续用卡片 + 独立编辑 Modal（模板做法）
   - 最强的理由：卡片墙在 4 个角色时确实好扫；Modal 能给编辑足够宽度和焦点圈禁。
   - 为何被否：12 个角色时卡片墙没有稳定扫描顺序；Modal 会遮住名册上下文；4000 字符 instructions 和字段级校验放不进一张卡，错误与保存入口分离。主从布局把“选谁”和“改谁”放在同一屏，列表可滚动，编辑器可增长。
4. 名册用表格行内编辑
   - 最强的理由：密度最高，12 个角色一屏能看全；字段对齐，便于比较 quota/route。
   - 为何被否：`instructions` 是长文本，行内编辑会把行撑成不可控高度；purpose/instructions/preset/route 的字段类型差异太大，表格会变成横向滚动。

## Consequences

- 收益：配置页稳定在三页签；12 个角色不撑爆页面；长文本编辑与校验有固定位置；运行视图不被设置项污染。
- 代价：会话绑定变得不那么“可发现”，依赖 chip 和右栏的只读提示；名册需要列表滚动与选中项保持，代码量比卡片墙大；handoff 未实现时用户看不到名册入口，需要文档/引导补足。
