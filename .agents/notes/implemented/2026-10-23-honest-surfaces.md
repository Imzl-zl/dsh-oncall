# Agent Note: 界面上的数字和"读不到"必须与事实同一口径

Status: implemented

## Problem

一次整仓审查暴露了四类同根问题，全都表现为"屏幕上说的和实际执行的不是一件事"：

1. 第一跳重试步进器用 `Number(props.maxRetries) || DEFAULT` 兜默认值，把合法的 0
   读成 5。界面显示 5、note 写 5，而同一页的预算公式按 0 算、草稿与宿主也按 0
   执行。说明文案自己写着"0 = 失败即切"。
2. 打开健康页会读宿主最近一次探测报告，并把 `ui.probe` 整份替换。宿主只保留
   "最后一次运行"，所以一次单条探测之后打开健康页，其它路由刚测出的结论被抹成
   "未探测"。
3. 转移历史是第二份"最近 20 个会话"读取：逐会话 `.catch(() => ({ entries: [] }))`
   把读失败折成"这个会话没有转移"。健康历史那轮修过同一句话，只修了其中一份。
4. 截断记录是单槽：辅助调用（会话标题、压缩）也写 `assistant/message`，一旦落在
   "被截断的那条"与 `turn-stopping` 之间，单槽被换成 `truncated:false`，自动续跑
   静默不发生。
5. 总闸只被 `agent/request` 读：步骤中途关闸，恢复侧仍按冻结的链换候选——开关说
   "关了"，实际还在换模型。

## Decision

界面只陈述能被同一份事实支撑的东西：数字取自草稿与宿主正在用的值；读取失败必须
单独渲染；宿主只保留"最后一次"的快照由浏览器按 key 合并；按 turn 记账的状态必须
带 step。

准入门槛（可机械判定）：

1. 合法零值：可选数值只用 `??` 或类型判断，不用 `||`；测试断言"0 显示为 0，且从
   0 加一步得到 1"。
2. 快照合并：凡读口是"最后一次运行"（`probeReport`），客户端按路由 key 合并，
   不整份替换。
3. 失败上屏：逐项读取失败累计后单独渲染（数量 + 原因）；"没有记录"的文案只在
   该次读取完整时出现。
4. 辅助事件隔离：按 turn 记账的状态带 step，别的 step 的消息不得覆盖本 step 的
   事实（同一 step 内仍后写赢）。
5. 总闸一致：两个缝都读同一个 `config.enabled`；总闸关着时任何一侧都不做决定。

## Alternatives considered

1. 让宿主改成"只保留跑遍全部路由的那一轮"，单条探测不写快照
   - 最强的理由：健康页本来就是按路由画一张表，"全量快照"正是它要的那份，客户端
     连合并都不用做。
   - 为何被否：`probeReport` = "最后一次运行"是现有 Remote 契约，remote 套件也按它
     断言；改成"只保留全量"会让单条探测的结果在刷新后凭空消失，改成"两个快照"则
     多一份需要同步的状态。把合并放在浏览器一侧，两边语义都不用动。
2. 转移历史继续保留自己的读取实现，只把逐会话 catch 改成 rethrow
   - 最强的理由：改动最小，一处 try/catch 就能让失败可见。
   - 为何被否：那仍是第二份"枚举 + 排序 + 截 20"的实现，失败口径与合并顺序已经漂过
     一次；rethrow 还会让一个坏会话把整份历史变成错误页，而其余十九条是好的。
3. 截断记录改成"只有 truncated=true 时才写"
   - 最强的理由：一行判断，辅助消息天然写不进去。
   - 为何被否：同一个 step 真出现第二条正常结束的消息时，旧结论会永远留着，反而
     变成假阳性；按 step 记账把"后写赢"限制在同一个 step 内。

## Consequences

- 收益：三处"屏幕上说了假话"的地方消失；两张视图共用一次读取，少一份实现；截断
  续跑不再被无关消息静默取消；空链的预算公式不再承诺一个不会发生的调用数。
- 代价：`ui.drawerPartial` 是一个新的界面状态（两个字典键）；合并式快照意味着宿主
  快照里没有的路由只能靠浏览器自己的记忆，刷新后仍会显示"未探测"（会话内正确）。
